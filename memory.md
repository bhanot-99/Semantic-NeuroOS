## ✅ RESOLVED 2026-09-27 — R0-1 violation in `neuroos-storage` (was 🔴 CRITICAL)

**Fixed via option 1 from the list below** (vendor-patch `lance-namespace` + `lance-namespace-reqwest-client`), confirmed with both `cargo tree -p neuroos-storage -i reqwest`/`-i hyper` (no matching packages — fully gone from the dependency graph, not just unused-but-linked) and `cargo deny check` (`bans ok`; the `reqwest`/`hyper`/`hyper-util` wrapper rules in `deny.toml` are now merely unused, not violated — left in `deny.toml` as-is, harmless and correct if any future dependency reintroduces one). Full test suite (51 unit + 5 real-model-and-lancedb `--ignored` tests) and `cargo clippy -- -D warnings` both pass with the patch in place.

**What was actually wrong, confirmed by reading the vendored sources**: `lance-namespace` 12.0.0's `Cargo.toml` has an unconditional, non-optional dependency on `lance-namespace-reqwest-client` 0.12.0, which has an unconditional, non-optional dependency on `reqwest` (no `[features]` section existed in either crate). But neither `lance` (12.0.0, `lancedb`'s dependency) nor `lancedb` itself ever references that crate's `apis` module (the only part that actually uses `reqwest` — confirmed by grep, zero hits) — both only use its reqwest-free `models` module (plain serde data types) and the `LanceNamespace` trait. So the fix is: make `reqwest` an optional dep gated behind a new `client` feature (default off) in `lance-namespace-reqwest-client`, gate its `apis` module and `extern crate reqwest` the same way, then have `lance-namespace` depend on it with `default-features = false` and gate its own `apis` re-export the same way. Nothing that was actually reachable from `neuroos-storage`'s code paths lost functionality.

**Files**: `vendor/lance-namespace-12.0.0-patched/` and `vendor/lance-namespace-reqwest-client-0.12.0-patched/` (new, alongside the pre-existing `vendor/lancedb-0.39.0-patched/`), each `[patch.crates-io]`'d in root `Cargo.toml` (see that file's comment for the full chain). Every edit has a `PATCHED` comment.
